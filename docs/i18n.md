# Internationalisation Foundation

Voice Studio treats i18n as reading behaviour, voice availability, and locale formatting, not only translated labels.

## Registry

`frontend/src/features/i18n/i18nRegistry.ts` owns the baseline UI string registry, language metadata, locale fallback, text direction, locale-aware number/date formatters, and speech-policy defaults by language.

## Voice Mapping

`frontend/src/features/i18n/languageVoiceMapping.ts` maps language metadata to available voice surfaces:

- Kokoro voicepacks are ordered by language match where Kokoro has a compatible language pack.
- Saved voice profiles are matched by normalized language code.
- Supertonic language choices are filtered by the active engine diagnostics when the backend reports supported languages.
- Unsupported languages keep the fallback voice list visible but no longer pretend every voice is a language match.

The Workspace voice picker uses this model to show language-match context before generation, and dashboards use locale-aware labels instead of raw language codes where practical.

## Validation

Run:

```sh
pnpm check
pnpm e2e:accessibility-audit
pnpm e2e:responsive-snapshots
pnpm e2e:ui-actions
pnpm validate:local
```

Manual QA should verify language selection changes available voices predictably, saved profiles advertise whether they match the current language, and dates/numbers remain readable in dashboard summaries.
